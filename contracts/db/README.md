# Объекты БД на стыке дорожек

Схема `app` (бизнес-данные, §7.2) принадлежит дорожке «Платформа»; дорожка «Устройство» работает с ней только через
объекты из [`app-interface.json`](app-interface.json) под ролью `app_device` (§6.3):

| Объект | Что даёт |
|---|---|
| `app.v_device` | устройство → арендатор, клиент, адрес, модель, жизненный цикл, блокировка |
| `app.v_device_schedule` | действующее расписание с версией и часовым поясом |
| `app.v_device_setting` | действующие настройки устройства, в том числе `ota_allowed`, `timezone` |
| `app.audit_append(...)` | запись аудита: provisioning (сертификаты, CERT), dispatcher (служебные действия с командами) |
| `app.schedule_store_local(...)` | расписание, изменённое на месте, — новой версией платформы; номер действующей версии |

Реализация — миграция [`services/api/drizzle/0001_contract.sql`](../../services/api/drizzle/0001_contract.sql);
тест `services/api/test/db.test.ts` сверяет базу с `app-interface.json` и проверяет, что прочих прав у `app_device` нет.
Изменение интерфейса — с одобрения обеих дорожек.

В обратную сторону (схема `telemetry` дорожки «Устройство»: команды и алерты, к которым Платформа пишет создание команд
и поля обработки алертов) — появится вместе со схемой `telemetry`.
